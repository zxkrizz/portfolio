## growth

        
Three years ago I was closing helpdesk tickets. Today I build the Terraform modules and pipelines other teams deploy with.

      

      

        

          
I learn by running things. Before I automated a server, I patched it by hand. Before I wrote Terraform for a network, I configured firewalls and VPNs by hand. Every layer I work on today is one I have operated myself, which is why I pick up new tools quickly and know where they tend to break.

          
That pace has not slowed down. In under three years I went from endpoints to on-prem infrastructure to enterprise Azure, earned nine certifications along the way, and most recently got certified in operating GPU infrastructure for AI workloads. I am looking for a team where that curve can keep going up.

    ## approach
    
        
    
          
    Infrastructure as code
    
          
    I define infrastructure in Terraform and deploy it through GitHub Actions. Every change goes through a pull request and a plan before anything is applied.
    
        
    
        
    
          
    Reusable building blocks
    
          
    When a team needs the same thing twice, I turn it into a module or a shared workflow with tags, networking and policies already in place.
    
        
    
        
    
          
    Recovery without a human
    
          
    Health checks and redundancy should handle the common failures on their own. You can test it here: click any pod in the cluster and it gets replaced.
    
        
    
        
    
          
    Monitoring
    
          
    I have set up Zabbix, Grafana, Datadog and Wazuh in on-prem and cloud environments. A good alert points at something a user would actually notice.
    
        
    
        
    
          
    On-call
    
          
    When something breaks I find the cause, fix it, and then write down or automate whatever would stop it from happening again.
