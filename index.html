## growth

        
From helpdesk tickets to running critical enterprise cloud infrastructure at scale. Every role handed me more scope than the last.

      

      

        

          
In every role so far, doing the job well has meant being given more of it: more systems, more responsibility and harder problems. I was trusted with production early, and each step came with a bigger scope rather than a fresh start. That is how I moved from support to on-prem infrastructure to enterprise cloud platforms so quickly.

          
It also means I learned every layer by running it. I patched servers before I automated them and configured firewalls and VPNs by hand before I described networks in Terraform, so I pick up new tools quickly and know where they tend to break.

    ## approach
    
        
    
          
    Nothing changes by hand
    
          
    If it runs in production, it is described in code and reaches production through a pipeline. That makes every change reviewable, repeatable and easy to roll back.
    
        
    
        
    
          
    Failures should fix themselves
    
          
    Health checks and redundancy handle the common failures, so people only deal with the unusual ones. Try it: click any pod in the cluster and watch it get replaced.
    
        
    
        
    
          
    Know before the users do
    
          
    Alerts point at what users would actually feel. When something does break, I find the root cause and automate it away, so the same page never fires twice.
    
        
    
      
    
    
    

    
    
      
    
        
    ## projects
    
        
    Projects
    
        
    Most of this runs in production at work, so the code stays private. Here is what each one does and what it changed.
    
      
    

      
    
        
    
          
    golden-images
    
          
        
    
        
    Hardened, CIS-checked base images for Windows and Linux, built, tested and published by GitHub Actions.
    
        
      
          
    1. terraform build VM
      2. 
          
    2. CIS hardening
      3. 
          
    3. ansible agents
      4. 
          
    4. tests + CIS scan
      5. 
          
    5. compute gallery
      6. 
        
    
        
    
          
    general purpose
    Linux distributions and Windows Server editions
    
          
    specialised
    purpose-built production images, such as self-hosted GitHub Actions runners
    
        
    
        
    
          
    why
    Every new VM should start secure and consistent, whatever the operating system, instead of being hardened and configured after it is already running.
    
          
    built
    A workflow per image: Terraform provisions a build VM, the CIS baseline is applied, Ansible installs the required agents, the image is tested and scanned for CIS compliance, then versioned into Azure Compute Gallery.
    
          
    result
    A catalogue of hardened images maintained as code. New machines come up compliant and fully configured on day one.
    
        
    
      
    

      
    
        
    
          
    
            
    vm-hardening
    
            
          
    
          
    A workflow that applies the same CIS baseline to Azure VMs that are already running, so older machines catch up with the golden images without being rebuilt.
    
          
    result one hardening standard for new and existing servers
    
        
    
        
    
          
    
            
    fleet-patching
    
            
          
    
          
    A self-hosted GitHub runner hands the job to Ansible, which installs packages and updates middleware across many hosts in parallel, on a schedule or on demand.
    
          
    result routine operations run automatically and middleware stays current across the estate
    
        
    
        
    
          
    
            
    monitoring-platform
    
            
          
    
          
    Centralised monitoring and alerting with Zabbix and Grafana for on-prem infrastructure across several locations: virtual machines, VMware hosts, SQL Server clusters, Veeam backups, switches, access points and UPS units.
    
          
    result problems detected in seconds instead of hours, usually before users noticed
    
        
    
        
    
          
    
            
    homelab
    
            
          
    
          
    A Proxmox cluster at home running Docker workloads, Proxmox Backup Server and Grafana. New tools get tested here long before they reach work.
    
          
    result a place to break things safely
